## Key Question 1: What is a Recipe? Fields, Cook mechanics, auto-cook vs manual cook

### Takeaway
A recipe is a list of "recipe lines" attached to a preset, a cue part or a programmer part; each line is a reference-based rule ("selection/group + values/preset + optional MAtricks/filter + per-axis fade/delay/speed/phase + grid/X/Y/Z settings") that the console "cooks" into concrete fixture/attribute values marked as cooked data. Editing or assigning a line auto-cooks it (MergeLowPriority); on 2.5.1 a change of an ingredient (group membership or preset content) is also re-cooked in the background a few seconds later (community-verified, not stated in the manual excerpts), but deleting cooked lines, removing fixtures or recovering recipe values over hard values requires a manual `Cook`, and hard (non-cooked) values always outrank recipe values unless cooked with `/Merge` or `/Overwrite`.

### Cited Findings

**Definition and where recipes live**
- "A recipe contains one or multiple recipe lines describing what should happen based on a set of information"; cooking writes values into a cue part, preset, or the programmer. — [MA manual 2.5, Recipes](https://help.malighting.com/grandMA3/2.5/HTML/recipes.html) [documented]
- Recipes were introduced in v1.4: "Recipes can be attached to presets, cue parts, and programmer parts. Recipes contain the ingredients fixture selection (groups), values (presets), MAtricks, fade, delay, speed, and phase. Cooking is the process of reading the ingredients and writing the data to the cue, preset, or programmer." Cook modes in 1.4: Merge, Overwrite, Remove; "cooked data is marked" and can later be removed with cook remove. "Step Recipes and the Step Creator are not anymore part of v1.4 or newer." — [Release Notes 1.4](https://help.malighting.com/grandMA3/2.4/HTML/key_rn_v1_4.html) [documented]
- Recipes are children of Presets, Cue Parts and Programmer Parts; as of v2.4.2.2 there are two recipe types, "Standard Recipes" and "Phaser Recipes". — [ACT Entertainment KB: Syntax for working with Recipes](https://support.actentertainment.com/knowledgeBase/34108761) [community]
- Recipe lines are objects of Lua class `StandardRecipe` (phaser lines: `PhaserRecipe`), children of the Part or Preset; addressed as `Sequence S Cue C Part P.L` or `Preset Pool.N.L`. — [gma3-mcp recipes.md](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/tools/recipes.md); [gma3-mcp SB-05 probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md) [community, verified on onPC 2.5.1.0]
- An older forum note: "there was an error in previous versions that allowed recipes to be added to cues when they should only be able to be added to cue PARTS" — recipes belong to parts (default part 0). — [MA forum via search](https://forum.malighting.com/forum/thread/8242-syntax-for-assigning-matricks-pool-item-to-recipe-line-in-sequence/) [community]

**Recipe line fields / Recipe Editor columns**
- A recipe line "can contain information about a selection of fixtures, group, preset, MAtricks, individual fade, delay, speed, and phase values" (2.2) and, per the cue-recipe page, "selection, values, MAtricks reference, filter, individual fade, delay, speed, phase values, and grid values". — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html); [Cue Recipes 2.3](https://help.malighting.com/grandMA3/2.3/HTML/cue_recipe.html) [documented]
- Selection column: shows group number and name; text turns red if the group is empty; if the selection came from the programmer it reads `<Recipe>`; `<From Value>` (SelectionFromValue) takes the fixtures of the preset as selection. — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html); [Recipe Editor 2.4](https://help.malighting.com/grandMA3/2.4/HTML/recipe-sheet.html) [documented]
- Values column: shows the preset (number, name, icons for Preset Mode / MAtricks etc.); orange = not all fixtures of the selection can use the preset; red = not compatible with the Selection. In 2.2 you cannot type raw values into a recipe line — values must live in a preset first; with no preset the recipe values go to the programmer. — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html) [documented]
- 2.4 added phaser recipes with per-step `Value Absolute` ("absolute value for an attribute, for instance a dimmer value of 50%") and `Value Relative` ("for instance a dimmer value of -20%"), plus Accel/Decel/Trans/Width per axis, Step, Shape, Attributes, NShot, Direction columns. Shapes assigned to a phaser recipe fill empty cells; manual values override shape values (shown in angle brackets). — [Features 2.4](https://help.malighting.com/grandMA3/2.4/HTML/rn_features-2-4.html); [Recipe Editor 2.4](https://help.malighting.com/grandMA3/2.4/HTML/recipe-sheet.html) [documented]
- Timing columns Fade, Delay, Speed, Phase each exist as From/To pairs (spread over the selection). — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html) [documented]
- Grid columns mirror MAtricks columns for the X, Y and Z axes. 2.2 added the MAtricks properties X, Y, Z to recipe lines and an `Enabled` column; 2.2.5.0 added a Lock column. — [Recipes 2.0](https://help.malighting.com/grandMA3/2.0/HTML/recipes.html); [Release Notes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/key_releasenotes.html) [documented]
- `Selection Mode` column (added 2.0): Normal passes values down to subfixtures; Strict applies values only to fixtures actually in the selection; recipes migrated from v1.9.7 or earlier are set to Strict. — [Release Notes 2.0](https://help.malighting.com/grandMA3/2.0/HTML/key_releasenotes.html); [Recipe Editor 2.4](https://help.malighting.com/grandMA3/2.4/HTML/recipe-sheet.html) [documented]
- Attributes column (2.4) is a dropdown filter with options All/Used/Unused/Selection; from 2.3 attribute filtering moved into the Filter pool (rule type Attributes). — [Recipe Editor 2.4](https://help.malighting.com/grandMA3/2.4/HTML/recipe-sheet.html); [Release Notes 2.3](https://help.malighting.com/grandMA3/2.3/HTML/key_releasenotes.html) [documented]
- Lua-visible property names of a `StandardRecipe` line on 2.5.1: references `Selection` (group handle), `Values`/`Preset` (preset handle), `MAtricks`, `Filter` (handles); settings `Enabled`, `SelectionMode`, `Name`, `SelectionFromValue`, the full MAtricks property set (XWings, XBlock, XGroup, XWidth, XShift, XShuffle, X, FadeFromX/FadeToX, DelayFromX/DelayToX, PhaseFromX/PhaseToX, SpeedFromX/SpeedToX and Y/Z equivalents) and per-axis `FadeX`, `DelayX`, `SpeedX`, `PhaseX`; status `FailedCookedPart` ("None"/"Group"/"Matricks") and `EmptyLastCooking` (Yes/No); also `Generator` is read by the bridge. — [gma3-mcp probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md); [gma3-mcp bridge plugin](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/plugin/gma3_mcp_bridge.lua) [community]
- Phaser-recipe/ACT property names: `Xinv`, `XinvG`, `XinvB`, `XinvW`, `InvertX` (Yes/No); `Y`, `YGroup`, `YBlock`, `YWings`, `YWidth` (number, "None", or "No____"); `Attributes` (attribute name/number or Filter reference); `Curve` ("Linear", "Ease In and Out", "Ease Out", "Ease In", "Snap", "Swing", "Reset"); `ValueAbsolute`/`ValueRelative` (preset objects or values); `RawValueRel` "None" clears a shape-derived relative value; `Shape` (a Shape object or another PhaserRecipe line in the same object); `Filter` (World or Filter object). Text values usually need a capitalised first letter. — [ACT KB](https://support.actentertainment.com/knowledgeBase/34108761) [community]
- Cue part properties relevant to recipes read via Lua on 2.5.1: `OwnDataPresent`, `OwnNonCookedDataPresent`, `MemoryType`; preset/part store options include `RecipeStoreMode`, `GridMergeMode`, `CueOnly`, `TrackingShield`. — [gma3-mcp bridge plugin](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/plugin/gma3_mcp_bridge.lua) [community]

**Cook mechanics**
- Syntax: `Cook [Object] ["Object_Name" or Object_Number] (/Option)`; options `/Merge`, `/MergeLowPriority`, `/Overwrite`, `/Remove`; e.g. `Cook Preset 1.1`, `Cook Preset 1.1 /Remove`, `Cook Sequence 6 /Overwrite`. Without an option a pop-up asks. — [Cook Keyword 2.2](https://help.malighting.com/grandMA3/2.2/HTML/keyword_cook.html) [documented]
- Option semantics (2.3/2.4 manual): **Merge** (default when nothing specified) removes values flagged as cooked, cooks the recipes and replaces values at the destination based on the ingredients; **MergeLowPriority** replaces existing cooked data and adds new recipe data but does not change non-cooked data; **Overwrite** deletes all contents of the target and cooks fresh (manual warns it "can be a very dangerous function"); **Remove** deletes data that was cooked but never updated. — [Cue Recipes 2.3](https://help.malighting.com/grandMA3/2.3/HTML/cue_recipe.html); [qsg_recipes 2.4](https://help.malighting.com/grandMA3/2.4/HTML/qsg_recipes.html) [documented]
- In v2.0 the former "Merge" behaviour was renamed MergeLowPriority. — [Release Notes 2.0](https://help.malighting.com/grandMA3/2.0/HTML/key_releasenotes.html) [documented]
- Verified matrix on onPC 2.5.1 with a hard value next to recipe output: `/MergeLowPriority` keeps hard values everywhere (including on the recipe's own fixture/attribute); `/Merge` keeps hard values on other fixtures/attributes but replaces the hard value on the recipe's own fixture+attribute; `/Remove` removes all cooked data, keeps hard values; `/Overwrite` deletes hard values, leaving only cooked data. A shrinking group under MergeLowPriority or Merge drops the cooked data of removed fixtures. — [gma3-mcp probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md) [community]
- Auto-cook: "Making changes to the recipe line automatically cooks the line using the merge option. Deleting an already cooked recipe line does not auto-cook. The recipe needs to be manually cooked to reflect the new result." Recipe lines without a group do not auto-cook. — [Recipes 2.5](https://help.malighting.com/grandMA3/2.5/HTML/recipes.html); [Cue Recipes 2.3](https://help.malighting.com/grandMA3/2.3/HTML/cue_recipe.html) [documented]
- MA staff (Sebastian) on the forum: auto-cook runs `Cook /MergeLowPriority` when recipes are created or changed and `/Remove` when they are deleted; "By default, auto-cooking doesn't touch values that have been manually stored to the Cue"; manual cooking is needed to re-apply recipe output over stored data. — [MA forum: When to cook manually?](https://forum.malighting.com/forum/thread/68353-when-to-cook-manually/) [community, staff answer]
- Priority: "Values in a cue part outrank the cue part's recipe value, and preset values outrank preset recipe values"; "Hard values have always priority on recipe values. You need to cook to recall recipe values." — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html); [MA forum thread 7878](https://forum.malighting.com/forum/thread/7878-problem-using-recipes-and-cooking/) [documented + community]
- Does a recipe re-cook when the group changes? The 2.5 feature text says "changing the ingredients leads to a re-cooking as such, and therefore updates all references". — [Release Notes 2.5](https://help.malighting.com/grandMA3/2.5/HTML/release-notes-2-5.html) [documented, excerpt]. Verified live on onPC 2.5.1.0: after overwriting a group (401,402 → 401–403) the cue part still showed the old coverage in the same Lua chunk, but ~3 s later read 401–403; shrinking back likewise; changing the referenced preset's content (R 50→20) also propagated after ~3 s; `Cook Sequence … /MergeLowPriority` applied it at once. — [gma3-mcp probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md) [community]. Earlier forum advice (pre-2.5): a moderator suggested cooking again after updating a group's contents, and "if fixtures were removed from the group, Cook Overwrite may be needed". — [MA forum thread 9186](https://forum.malighting.com/forum/thread/9186-phaser-preset-reference-broken-when-changing-selection-in-recipe/) [community]
- 2.2 bug-fix: "recipes of cues containing the exchanged fixtures had to be recooked or merged again after patch exchanges" (fixed in 2.2). — [Release Notes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/key_releasenotes.html) [documented]
- Cooked data is flagged: cooked values show a small green marker in the upper right corner in the Track Sheet; via Lua `GetPresetData` on a Part returns `mask_cooked` 511 for cooked and 0 for hard values (2.5.1). — [MA forum thread 68814](https://forum.malighting.com/forum/thread/68814-recipe-vs-stored-data-in-sequence-indication-management/); [gma3-mcp probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md) [community]
- Pot icons (2.4/2.5): green pot = last cook of all lines succeeded; red pot = at least one line failed; orange pot = mixture of cooked and uncooked data; recipe templates show a pot with an open lid. — [Recipes 2.5](https://help.malighting.com/grandMA3/2.5/HTML/recipes.html); [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html) [documented]
- Ordering: "If several recipe lines with the same selection refer to the same attribute, the last recipe line determines the output"; cooking reads recipe lines in order. — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html); [Release Notes 1.4](https://help.malighting.com/grandMA3/2.4/HTML/key_rn_v1_4.html) [documented]
- Cooked output can include the rest of an activation group (a red preset with R,G,B also cooks W, RY, UV of an RGBW fixture). — [gma3-mcp recipes.md](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/tools/recipes.md) [community]
- 2.1 feedback improvement: empty groups, presets the selection cannot use, MAtricks that cannot cook, and blocking filters turn the cell text red; partially cooked selection turns orange. — [Release Notes 2.1](https://help.malighting.com/grandMA3/2.1/HTML/key_releasenotes.html) [documented]

### Inferences
- "Recipe" (the rule) and "cooked values" (the materialised data) coexist in the same part/preset; cooked values are ordinary tracked cue data with a cooked flag, so playback (tracking, release, fade) operates on cooked values, not on the recipe at runtime. [inferred from the mask_cooked flag and "hard values vs cooked" behaviour]
- For a generator producing recipe-based cues, the safe post-generation step is an explicit `Cook Sequence N /MergeLowPriority` (or `/Merge` if the generator also stored hard values that should be superseded); rely on auto-cook only for freshly created lines. [inferred]
- Background re-cook on ingredient change appears to be a 2.5-era behaviour; on earlier 2.x versions assume a manual Cook is required after group edits. [inferred from the conflict between 2.5 excerpt/probe and older forum advice]

- Could not read the full official 2.5 manual pages (host blocked), so exact wording of Merge vs MergeLowPriority and the pot-icon list for 2.5 is from excerpts.
- No official statement found about when (which version) background re-cook on group/preset change was introduced.

## Key Question 2: How are recipes represented in exported Sequence / Preset XML?

### Takeaway
No available source documents or shows the XML serialisation of recipe lines; the only facts are that MA3 import/export is XML with a `<GMA3 DataVersion="…">` root, that recipe lines are objects of class `StandardRecipe`/`PhaserRecipe` with the Lua-visible property names above, and that MA3 XML serialises objects with their properties as attributes — so the element/attribute names below are an inference to be verified by exporting a sample sequence.

### Cited Findings
- "MA uses xml for all its import / export functionality"; the Export keyword writes a separate XML file per pool object when several objects are exported without a file name; sequence XML files are placed in `grandMA3/export/` on the USB and imported into an empty sequence slot with `Import Sequence`. — [MA forum: Copy Recipe Lines Plugin](https://forum.malighting.com/forum/thread/9152-copy-recipe-lines-plugin/); [Export Keyword 2.0](https://help.malighting.com/grandMA3/2.0/HTML/keyword_export.html); [MLA docs](https://www.manula.com/manuals/avld/mla/14/en/topic/importing-sequence-and-timecode-files-into-the-grandma3) [documented/community]
- MA3 plugin XML files have a root `<GMA3 DataVersion="x.y.z.w">` with the object as a child element (e.g. `/GMA3/UserPlugin/@Version`, `/GMA3/@DataVersion` XPath used in README badges). — [patopesto/GrandMA3-Plugins README](https://raw.githubusercontent.com/patopesto/GrandMA3-Plugins/master/README.md) [community]
- Recipe line object classes are `StandardRecipe` and `PhaserRecipe`; their properties (Selection, Values/Preset, MAtricks, Filter, Enabled, SelectionMode, Name, SelectionFromValue, XWings…, FadeFromX…, FailedCookedPart, EmptyLastCooking) are listed under Key Question 1. — [gma3-mcp probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md) [community]
- A community "Copy Recipe Lines" plugin exports recipe lines to a file named `copyRecipeLines.xml` (plugin-specific, not the native sequence format). — [MA forum thread 9152](https://forum.malighting.com/forum/thread/9152-copy-recipe-lines-plugin/) [community]
- A 2025 forum thread reports that after a DataPool export/import, references were repaired by hand-editing the generated XML to point at the new datapool name, i.e. references inside exported XML are textual object paths/names. — [MA forum thread 68636](https://forum.malighting.com/forum/thread/68636-datapool-import-export-workflow-lost-references/) [community]
- Exported layouts reference objects by name (official forum reply). — [MA forum thread 68044](https://forum.malighting.com/forum/thread/68044-import-export-of-layouts-leaves-objects-empty/) [community]

### Inferences
- [inferred, unverified] Based on MA3's generic object serialisation (class name as element, properties as attributes, children nested), a recipe line in an exported sequence most likely appears as something like:
  ```xml
  <GMA3 DataVersion="2.5.x.x">
    <Sequence Name="Song 1" ...>
      <Cue Name="Cue 1" No="1000" ...>            <!-- cue numbers are x1000 internally -->
        <Part Name="Part 0" ...>
          <StandardRecipe Name="Recipe 1" Enabled="Yes" SelectionMode="Strict"
                          Selection="ShowData.DataPools.Default.Groups.Group 1"
                          Values="ShowData.DataPools.Default.PresetPools.Color.Red"

        </Part>
      </Cue>
    </Sequence>
  </GMA3>
  ```
  The exact attribute spellings, whether references are stored as paths, names or handle numbers, and how cooked values are serialised (if at all) must be confirmed by exporting a small sequence from onPC (`Export Sequence 1 "test"`), which could not be done here. Cue numbers reading ×1000 in Lua (`no` 1000 = cue 1) is verified. — [gma3-mcp probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md)
- Because the console re-cooks on import/edit and references are resolved by object path/name, generating XML with recipe lines but no cooked data is probably viable (cook after import), whereas generating cooked values in XML would require replicating the fixture data serialisation. [inferred]

## Key Question 3: Command syntax and Lua API to create recipe lines

### Takeaway
Recipe lines are created implicitly by `Assign <Group|Preset|MAtricks|Shape> <n> At <target> Part P.L` (or `Preset Pool.N.L`), where a non-existent line index creates the line (appended with no gap), and all other columns are set with `Set <line> Property "<Name>" "<value>"`; in Lua a line's properties can be read/written via the object handle (`Selection` expects a group handle, not a string), but creating lines via `part:Insert()`/`Append()` is reported broken on 2.4+, so the robust programmatic path is `Cmd()` with the Assign/Set syntax, then `Cook`.

### Cited Findings

**Command-line (verified on 2.5.1 or widely reported)**
- `Assign Group 908 At Sequence 9060 Cue 1 Part 0.1` (no line yet) → line 1 created with that selection; `Assign Preset 4.4 At Sequence 9060 Cue 1 Part 0.1` → sets values; `Assign MAtricks 12 At … Part 0.1` → MAtricks reference (inherited columns read `<2>`); assigning to `Part 0.9` when 3 lines exist appends as line 4 (no gap); `Move … Part 0.2 At … Part 0.1` swaps order; `Delete … Part 0.2 /NoConfirmation` removes and re-cooks remaining lines; `Assign Group 908 At Preset 23.921.1` creates line 1 on an existing empty preset ("Illegal object" if the preset does not exist); a failed `Assign Shape 1 At Preset 23.921.2` left an empty line behind. The Assign itself cooked the line (OwnDataPresent Yes); `Set("Enabled","No")` removed its output; `Set("Enabled","Yes")` re-cooked. — [gma3-mcp probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md) [community, verified 2.5.1.0]
- Forum-reported forms: `Assign Group x At Seq y Cue 1 Part 0.1`; programmer: `Assign Group X At Programmer Y.Z` (Y = part, Z = recipe); preset: `Assign Group a At Preset x.y.z` (x = pool, y = preset, z = recipe line); wildcard `Assign Group 2 At Cue 1 Thru Part *.*` (warning: `Cue 1 Thru` also hits the OffCue); tag-filtered `Assign Group 1 At Seq x Thru Cue … Thru Part *.* If Tag y`; named line `Assign Group 1 At Part 0."myBrandNewRecipe"` (name must contain letters). Some users create the line first with `Store Cue x Part y.z`. — [MA forum thread 4782](https://forum.malighting.com/forum/thread/4782-assign-group-at-recipe-in-command-line/); [thread 8522](https://forum.malighting.com/forum/thread/8522-change-recipe-selection-in-a-sequence-via-cli/); [thread 7909](https://forum.malighting.com/forum/thread/7909-cmd-to-change-selection-group-in-recipe/) [community]
- Property set syntax: `Set Sequence a Cue b Part c.d Property "Selection" "" "Values" "" "MAtricks" "" "Filter" ""` (c = part, d = recipe line; empty string clears); `Set Preset a.b.c Property "XWings" d`; `Assign MAtricks x At Sequence y Cue z Part a.b`. — [ACT KB](https://support.actentertainment.com/knowledgeBase/34108761); [MA forum thread 8242](https://forum.malighting.com/forum/thread/8242-syntax-for-assigning-matricks-pool-item-to-recipe-line-in-sequence/) [community]
- Phaser-recipe commands collected by users (2.4+/2.5): assign presets to recipe steps in presets, cue parts and shapes; set `"ValueRelative" "40"` (percent), `"ValueAbsolute"`; shape playback props `"PlaybackNShot" 10`, `"PlaybackAdaptiveMeasure" "Yes"`; set `Enabled` "No" on a cue-part line to disable; "Swap Phase" only works on `PhaseFromX`/`PhaseToX`, not `PhaseX`. — [MA forum: Commands for new Recipe (May 2026)](https://forum.malighting.com/forum/thread/69919-commands-for-new-recipe/) [community]
- Preset conversion: Edit Settings → "Turn into Recipe" converts a preset with values into a recipe (`<Recipe>` appears in Values); the UI only allows adding recipe lines to presets without attribute values (1.7+). New/converted recipe presets are stored as Selective (2.4). — [Release Notes 1.7](https://help.malighting.com/grandMA3/2.2/HTML/key_rn_v1_7.html); [Recipe Presets 2.2](https://help.malighting.com/grandMA3/2.2/HTML/presets_recipes.html); [Features 2.4](https://help.malighting.com/grandMA3/2.4/HTML/rn_features-2-4.html) [documented]
- `/Recipe` option keyword exists (page title "/Recipe Option Keyword", 2.2) — content not retrievable. — [ok_recipe 2.2](https://help.malighting.com/grandMA3/2.2/HTML/ok_recipe.html) [documented, content unknown]

**Lua**
- Lines are read with `part:Children()` and `GetClass() == "StandardRecipe"`; properties via `Get`/`Set` (e.g. `textProp(r,"Selection")`, `"Preset"`, `"Values"`, `"MAtricks"`, `"Filter"`, `"FadeX"`, `"Enabled"`, `"SelectionMode"`, `"Generator"`); `r:Index()` gives the line index; `GetPresetData(part)` works on a cue Part as on a preset and reports `mask_cooked`. Hard (non-recipe) fixture values stored in a cue part are not exposed by the 2.5.1 Lua API (no GetCueData). — [gma3-mcp bridge plugin](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/plugin/gma3_mcp_bridge.lua) [community]
- Setting Selection in Lua: "the selection property expects an object-handle not a string with the name of the group", e.g. `recipeLine.SELECTION = DataPool().Groups[groupName]`; reading: `Root().ShowData.DataPools.Default.Sequences[n][1][1].Selection.Name`. — [MA forum thread 68826](https://forum.malighting.com/forum/thread/68826-assign-selection-recipe-line-lua/); [thread 9143](https://forum.malighting.com/forum/thread/9143-retrieving-the-selection-used-in-a-sequence-recipe/) [community]
- Creating lines in Lua: a June 2026 forum post reports that since 2.4 a sequence/cue/part can be created in Lua but a recipe cannot be created with `part:Insert(1)` (it worked in 2.3.2.0); no answer found. Creating a cue with `seq:Append()` does not create its part — call `cue:Create(1)` and allow a short delay (coroutine yield) before setting properties. — [MA forum via search](https://forum.malighting.com/forum/thread/69760-calling-nil-value-when-creating-sequence-through-lua/) [community]
- `Children()` returns a 1-indexed table; `Set` is a method on handles (`obj:Set(...)`); `ObjectList("Sequence 1 Cue 1 Part 0")` resolves a 0-based part from a command-line path. — [MA forum thread 8432](https://forum.malighting.com/forum/thread/8432-get-part-properties-with-lua/) [community]
- The gma3-mcp generator writes recipe cues entirely with `Cmd` strings: per line `Assign Group G At <line>`, (`set Enabled No`), `Assign Preset N.M At <line>`, `Assign MAtricks M At <line>`, then `set` SelectionMode/Name/columns (`None` for null), `Enabled Yes`; `replace` mode first `Delete <part>.<L> /NoConfirmation` from the last line; cue name on Part 0, note on the Cue; then `Cook <scope> /MergeLowPriority|/Merge|/Overwrite|/Remove`. Limits it imposed: ≤100 cue parts, ≤200 lines/part, ≤500 lines/call. — [gma3-mcp recipes.md](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/tools/recipes.md) [community]
- Dangling references: deleting the referenced preset leaves `Values` empty; deleting the group leaves `Selection` empty with `FailedCookedPart "Group"`; an empty group cooks nothing. — [gma3-mcp probe](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/probes/sb-05-recipes-macos-2.5.1.md) [community]

### Inferences
- For an external generator, the most portable approach across 2.x is to emit a macro or Lua `Cmd()` script of `Assign … At Sequence S Cue C Part P.L` / `Set … Property …` lines followed by `Cook Sequence S /MergeLowPriority`, rather than hand-crafted XML or Lua object creation. [inferred from the above]
- Cue-level timing (CueInFade etc.) is set on the Part/Cue with normal `Set` commands; recipe lines only carry per-fixture individual fade/delay spreads. [inferred]

## Key Question 4: Limitations and interactions (raw values, phasers, per-fixture values, selective presets, tracking/release/cue-only, performance, version history)

### Takeaway
Recipes are reference-based by design: standard lines take values only from presets (raw values came with phaser recipes in 2.4 via Value Absolute/Relative), distribution across a group follows the selection grid via MAtricks (so phase/width need adaptive settings or recalculation when fixture counts change), hard per-fixture values can live alongside but override recipe output, and cooked data is ordinary cue data for tracking/release; copying cues with status or using Block creates hard (non-recipe) values and there is no built-in "convert cue to recipe".

### Cited Findings
- No raw values in standard recipe lines (2.2): values must be stored in a preset first; empty preset → values go to programmer. — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html) [documented]. 2.4 phaser recipes accept `Value Absolute` (e.g. dimmer 50%) and `Value Relative` (e.g. -20%). — [Features 2.4](https://help.malighting.com/grandMA3/2.4/HTML/rn_features-2-4.html) [documented]
- Phaser recipes (2.4) = recipes with 2 or more steps; steps added with "New Step"; shapes assignable; 2.4 limitation: phaser recipes could not be created in Edit Recipe mode (standard only); PSR (partial show read) loses links to referenced shapes. 2.5: Edit Recipe Mode available for phaser recipes; context area for all columns; if more than one phaser recipe is in a preset, additional phaser recipes reference the first. — [Features 2.4](https://help.malighting.com/grandMA3/2.4/HTML/rn_features-2-4.html); [Release Notes 2.5](https://help.malighting.com/grandMA3/2.5/HTML/release-notes-2-5.html); [What's new 2.5](https://help.malighting.com/grandMA3/2.5/HTML/news.html) [documented]
- Fixture-count dependence: "distributed values depend on your selection GRID, not selection COUNT"; a user needed to recalculate phases when going to 3 fixtures; the same 3-fixture selection gave different values depending on grid gaps. — [MA forum thread 7661](https://forum.malighting.com/forum/thread/7661-width-and-phases-in-recipes/) [community]. Mitigations: 1.7 phase ranges auto-recalculate to the number of fixtures so first/last do not share a phase; 2.0 MAtricks X/Y/Z are relative to the entire range of selected fixtures; 2.4 "Adaptive Measure" sets measure to the number of fixtures along one axis and "Adaptive Width" adapts the first step's width to the number of grid positions. — [Release Notes 1.7](https://help.malighting.com/grandMA3/2.2/HTML/key_rn_v1_7.html); [Release Notes 2.0](https://help.malighting.com/grandMA3/2.0/HTML/key_releasenotes.html); [Features 2.4](https://help.malighting.com/grandMA3/2.4/HTML/rn_features-2-4.html) [documented]
- 2.1 fix: recipes could not be cooked when the selection did not start at grid 0/0/0 and MAtricks had X/Y/Z set. — [Release Notes 2.1](https://help.malighting.com/grandMA3/2.1/HTML/key_releasenotes.html) [documented]
- Per-fixture hard values: can coexist in the same part; they outrank recipe output; the system tracks only which cue part a value belongs to, not which recipe line; "a cooked-data cleanup will remove all non-recipe values from the cooked object" (i.e. `/Overwrite`). — [MA forum thread 68814](https://forum.malighting.com/forum/thread/68814-recipe-vs-stored-data-in-sequence-indication-management/); [thread 68353](https://forum.malighting.com/forum/thread/68353-when-to-cook-manually/) [community]
- Copy/Block create hard values: "copying cues with status or using block will create values without a recipe"; cues made with "cue only" or "copy status" store hard values; no built-in cue→recipe conversion exists ("desired by many, but does not yet exist", early 2025). — [MA forum thread 8922](https://forum.malighting.com/forum/thread/8922-cue-hard-values-to-cue-recipe/); [thread 68425](https://forum.malighting.com/forum/thread/68425-transform-cue-to-recipe/) [community]
- Tracking/cue-only: recipe output is tracked like stored data; workaround to prevent tracking of a part's data is tracking distance delta+0, but a recipe in an earlier cue still tracks forward; the cue-only store/update option only acts when at least one later cue exists. — [MA forum thread 68814](https://forum.malighting.com/forum/thread/68814-recipe-vs-stored-data-in-sequence-indication-management/); [thread 69565](https://forum.malighting.com/forum/thread/69565-protect-from-tracking-dimmer-cue-only/) [community]
- Selective vs global vs universal presets in recipes: a preset reference in a cue part is resolved by preset priority; a recipe line's cooked coverage follows the fixture's own selective row, the global row of its fixture type, or a universal row the fixture has the attribute for. — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html); [gma3-mcp recipes.md](https://raw.githubusercontent.com/bdstark/gma3-mcp/main/docs/tools/recipes.md) [documented/community]
- Universal preset problems reported: universal preset in a recipe applied only to the first fixture of the group (Feb 2025); universal recipe phasers do not work for slotted attributes such as colour wheel C1 unless the Universal fixture has a placeholder for the attribute (Aug 2025, staff view); universal XY colour presets needed the attribute added to the universal fixture (tech support, Nov/Dec 2025); adding a selection to a recipe turns clean universal presets into universal+selective (May/June 2026). — [MA forum 68625](https://forum.malighting.com/forum/thread/68625-universal-presets-in-recipies-not-working/); [69308](https://forum.malighting.com/forum/thread/69308-universal-fixture-missing-c1/); [69550](https://forum.malighting.com/forum/thread/69550-universal-color-preset-dosnt-work/); [69925](https://forum.malighting.com/forum/thread/69925-universal-recipe-phaser-presets-without-selective/) [community]
- Recipe templates vs recipe presets: a preset with "Recipe Template" enabled loads its recipe into the programmer part and cooks there (open-lid pot icon); a template placed in a cue does not follow updates to the source preset — use a regular recipe preset referenced from the cue. — [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html); [MA forum 68827](https://forum.malighting.com/forum/thread/68827-recipe-presets-and-recipe-templates-not-updating-in-cues/) [community]
- Calling a recipe preset with no values cooks its recipes into the programmer (1.4). — [Release Notes 1.4](https://help.malighting.com/grandMA3/2.4/HTML/key_rn_v1_4.html) [documented]
- Version history summary: 1.4 introduced recipes (Merge/Overwrite/Remove; step recipes removed); 1.7 recipe lines on empty presets, "Turn into Recipe", phase-range recalculation; 1.7.2.2 crash fixes for recipes without selection; 1.9 fixes (copying cues with recipes no longer creates extra parts; undo on recipes); 2.0 Selection Mode (Normal/Strict), MergeLowPriority rename, MAtricks X/Y/Z relative to range; 2.1 red/orange cook feedback, grid-origin cook fix; 2.2 Recipe Editor window + Edit Recipe mode, Enabled column, X/Y/Z on lines, patch-exchange recook fix, Lock column (2.2.5.0); 2.3 attribute filtering in Filter pool; 2.4 Phaser recipes, Value Absolute/Relative, Shapes, Adaptive Measure/Width, Attributes column; 2.5 Edit Recipe mode for phaser recipes, context area for all columns, multi-phaser-recipe referencing in a preset. — [RN 1.4](https://help.malighting.com/grandMA3/2.4/HTML/key_rn_v1_4.html); [RN 1.7](https://help.malighting.com/grandMA3/2.2/HTML/key_rn_v1_7.html); [RN 1.9](https://help.malighting.com/grandMA3/2.5/HTML/key_rn_v1_9.html); [RN 2.0](https://help.malighting.com/grandMA3/2.0/HTML/key_releasenotes.html); [RN 2.1](https://help.malighting.com/grandMA3/2.1/HTML/key_releasenotes.html); [RN 2.2](https://help.malighting.com/grandMA3/2.2/HTML/key_releasenotes.html); [RN 2.3](https://help.malighting.com/grandMA3/2.3/HTML/key_releasenotes.html); [Features 2.4](https://help.malighting.com/grandMA3/2.4/HTML/rn_features-2-4.html); [News 2.5](https://help.malighting.com/grandMA3/2.5/HTML/news.html) [documented]
- Current release as of Oct 2026: 2.5.1.1 listed on MA's download page; no 2.6 release notes found. — [MA downloads](https://www.malighting.com/downloads/products/grandma3/) [documented]

### Inferences
- Because recipes cannot express individual per-fixture values (other than via a selective preset or a phaser-recipe absolute value applied to the whole selection), an MA2→MA3 converter can only make "recipe-able" the cue content that is expressible as group × preset (+MAtricks spread); fixture-specific one-offs must remain hard values (and will then override recipes). [inferred]
- "Effect wings"/distribution equivalents are handled through MAtricks references or per-line XWings/XBlock/XGroup columns, which scale with grid positions rather than fixture count — adaptive measure/width (2.4+) is the intended fix for rig-size changes. [inferred]
- No performance data for cooking large shows was found; the gma3-mcp tool self-limits to 200 cue parts per cook and ~500 lines per call, suggesting cooking is not instantaneous but no timings were published. [inferred]

## Key Question 5: Best-practice workflows for fixture-count-independent shows and what breaks

### Takeaway
The documented pattern is: build groups per role, store Global (or Universal) presets, write cues as recipe lines (group + preset + MAtricks), then on a new rig re-patch, update the groups and `Cook Sequence N` — selective presets, per-fixture hard values, copied/blocked cues and grid-dependent phase/width are what break or need manual attention.

### Cited Findings
- Manual: "the flexibility in updating a few groups and then re-cooking an entire sequence makes the recipes a unique and very flexible tool when you often have to make adjustments to your show setup - for instance in a touring show"; recipes "can be a very useful tool for touring shows or when the changes are expected". — [qsg_recipes 2.5](https://help.malighting.com/grandMA3/2.5/HTML/qsg_recipes.html); [Recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/recipes.html) [documented]
- Quick start guide flow: create Universal presets as base presets, build recipe lines referencing groups and presets, `Cook Sequence 6` (pop-up asks the option), edit groups and re-cook; Overwrite used when the cues should contain only recipe content (example: group reduced to two fixtures → overwrite stores only those two); added fixtures are not automatically cooked into the programmer. — [qsg_recipes 2.2](https://help.malighting.com/grandMA3/2.2/HTML/qsg_recipes.html) [documented]
- Preset types vs rig changes: "If the fixture type changes, the global preset needs to be updated. The selective preset links to the global preset values and does not need to be updated. The universal fixture is unaffected by the fixture change." Global data sits on one fixture per type and moves to the first patched fixture of that type if that fixture is deleted or gets selective data. — [Presets 2.2](https://help.malighting.com/grandMA3/2.2/HTML/presets.html) [documented]
- Recast Preset refreshes cues referencing a preset after its attributes change. — [Recipe Presets 2.2](https://help.malighting.com/grandMA3/2.2/HTML/presets_recipes.html) [documented]
- Training content (ConsoleTrainer): "putting recipes in cues can be easier if you expect to change the fixture groups"; MAgic presets = global templates acting on selected fixtures; template recipe presets avoid hard values in cues; recipes "got a big overhaul with Version 2.4". — [ConsoleTrainer 22](https://consoletrainer.com/22-recipe-presets-grandma3-for-grandma2-programmers/); [ConsoleTrainer 23](https://consoletrainer.com/23-cue-and-programmer-recipes-grandma3-for-grandma2-programmers/); [ConsoleTrainer 2.5 updates](https://consoletrainer.com/ma3-version-2-5-recipe-updates/) [community]
- Community showfile example: a busking StartShow built on recipe lines with a single grid/linear-select group applied to the recipe line and worlds on phaser faders, reported as stable against patch/group/preset changes. — [MG_MA3_StartShow README](https://raw.githubusercontent.com/MichaelGreenNZ/MG_MA3_StartShow/main/README.md) [community]
- What breaks: hard values override recipes until re-cooked with /Merge or /Overwrite; copy-status/Block produce hard values; phase/width distributions depend on grid, not count; universal presets have known gaps for slotted attributes; dangling group/preset references leave empty Selection/Values fields. — see citations in Key Questions 1 and 4.

### Inferences
- For a converter producing portable MA3 shows: (1) emit groups per logical role, (2) emit Global presets per feature group (Universal where fixture-type-agnostic, noting the universal-fixture attribute caveats), (3) emit cues as recipe lines (one line per group×preset, MAtricks for spreads), (4) emit a `Cook Sequence N /MergeLowPriority` macro, and (5) keep any unavoidable per-fixture data as hard values in a separate cue part so Overwrite cooks on recipe parts do not destroy them. [inferred]

### Gaps
- No single authoritative MA "touring best practice" document was found; guidance is assembled from the quick-start guide and forum posts.

## Key Question 6: Community tools/plugins that generate recipes or convert cues to recipes

### Takeaway
There is no known tool that converts existing cues to recipes; the available tools are ma.tools' RecipeTools/Recipe Editor plugin (programmer → recipe lines, partly superseded by the built-in Edit Recipe mode since 2.3), a forum "Copy Recipe Lines" plugin, and the open-source `bdstark/gma3-mcp` MCP server whose `gma3_store_recipe_cues` tool writes up to 100 recipe cue parts per call via Assign/Set/Cook commands against onPC 2.5.1.

### Cited Findings
- ma.tools plugin "will convert your programmer data to recipe lines" (users called it the MA Tools Recipe Editor; worked on 2.2.5.2; after 2.3.1.1 it uses the built-in edit recipe function); ma.tools currently lists RecipeTools and BPMTimes (BPM timings to cues, recipe lines and programmer attributes); AdvancedUpdate requires 2.5.0.0+. — [MA forum 68425](https://forum.malighting.com/forum/thread/68425-transform-cue-to-recipe/); [ma.tools](https://ma.tools/); [AdvancedUpdate](https://ma.tools/AdvancedUpdate/) [community]
